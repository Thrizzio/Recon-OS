# Security Policy

- **Purpose:** Describe how to report vulnerabilities and what to expect.
- **Audience:** Security researchers and contributors.
- **When to update:** When supported versions or contacts change.
- **Expansion:** Add an incident-response runbook as the project matures.

## Security philosophy

Recon-OS is infrastructure for production systems, so security is treated as a first-class
concern, not a final step. We prefer coordinated disclosure and timely fixes over silence
or publicity.

## Supported versions

| Version               | Supported                |
| --------------------- | ------------------------ |
| `main`                | Yes (development branch) |
| Latest stable release | Yes                      |
| Older releases        | No                       |

> Replace this table with concrete release lines once the first stable version is tagged.

## Reporting a vulnerability

Please report security issues privately. Do **not** open a public issue for vulnerabilities.

1. Use GitHub's private vulnerability reporting for this repository, or
2. Email the maintainers at `<SECURITY_CONTACT@example.com>` _(placeholder)_.

Include:

- A description of the vulnerability and its impact.
- Steps to reproduce or a proof of concept.
- Affected versions and environment.
- Any suggested mitigation, if known.

## Response expectations

- **Acknowledgement:** within 72 hours of a complete report.
- **Triage:** within 7 days, with a severity assessment.
- **Fix or mitigation:** timeline communicated based on severity.
- **Disclosure:** coordinated with the reporter; public advisory after a fix ships.

## Safe harbor

We will not pursue legal action against researchers who act in good faith, report
responsibly, and avoid privacy violations or service disruption.
